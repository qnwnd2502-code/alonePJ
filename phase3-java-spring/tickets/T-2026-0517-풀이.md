# T-2026-0517 풀이 — 공지사항 검색 (졸업 기준표 1번)

추적 시간 : **20분** (목표 30분). 두 번째 결함에서 힌트 1회.

## 결함 1 — 검색어가 사라진다

```
bbsList.html    <input name="searchWrd">          ← 화면의 이름표
BoardVO.java    private String searchKeyword      ← VO 의 칸 이름
```

`@ModelAttribute` 는 **이름으로 짝을 맞춘다.** `searchWrd=예산` 이 오면 스프링은 `setSearchWrd()` 를 찾고,
없으면 **아무 말 없이 버린다.** `searchKeyword` 는 기본값 `""` 로 남고, XML 의
`<if test="searchKeyword != ''">` 가 거짓이 되어 검색 조건 줄이 통째로 빠진다.

```
① 화면        <input name="searchKeyword"> 에 "예산"
② Controller  @ModelAttribute BoardVO  → setSearchKeyword("예산")   ★ 이름으로 짝을 맞춘다
③ Service     bbsMapper.selectBbsList(searchVO)
④ XML         #{searchKeyword}  → getSearchKeyword()
⑤ SQL         AND ntt_sj LIKE '%' || ? || '%'     Parameters: 예산
```

**이름이 곧 연결선이다.** 화면의 이름표 = VO 의 칸 = XML 의 `#{}`.

수정 : 화면(`bbsList.html`)의 이름을 `searchKeyword` 로. VO 를 바꾸면 같은 VO 를 쓰는 다른 화면이 전부 영향을 받는다.
**고칠 곳이 여러 군데면 영향이 제일 작은 쪽을 고친다.**

## 결함 2 — 3건인데 페이지가 3개

```
① 목록 SQL   WHERE use_at = 'Y' AND ntt_sj LIKE '%' || ? || '%'   → 3건
② 건수 SQL   WHERE use_at = 'Y'                                     → 25건  ← 검색 조건 없음
```

전자정부 목록 화면은 **목록 SQL + 건수 SQL** 이 한 세트다(`selectXxxList` / `selectXxxListCnt`).
건수가 페이지 번호를 만든다. 둘의 조건이 다르면 화면엔 3건인데 페이지는 3개, 2·3페이지는 빈 화면.

수정 : 건수 SQL 에도 같은 `<if>` 조건. → 예산 검색 3건 / 1페이지, 검색어 없이 25건 / 3페이지.

## 선배 리뷰 — 조건은 한 곳에

같은 조건을 두 군데 복사해두면, 다음에 조건을 추가할 때 **한 쪽만 고쳐진다.** 이번 결함이 그렇게 생겼다.

```xml
<sql id="searchWhere">
     WHERE use_at = 'Y'
    <if test="searchKeyword != null and searchKeyword != ''">
       AND ntt_sj LIKE '%' || #{searchKeyword} || '%'
    </if>
</sql>

<select id="selectBbsList" ...>    SELECT ... FROM comtnbbs <include refid="searchWhere"/> ORDER BY ...
<select id="selectBbsListCnt" ...> SELECT COUNT(*) FROM comtnbbs <include refid="searchWhere"/>
```

발주처 소스에서 목록 SQL 과 건수 SQL 의 조건이 **따로따로 복사**돼 있으면 이 버그가 숨어 있을 확률이 높다.

## 3줄

1. 이름이 곧 연결선이다. 화면 이름표 = VO 칸 = XML `#{}`
2. 목록 SQL 과 건수 SQL 은 같은 조건을 쓴다
3. 에러 없는 버그는 실제 실행된 SQL 로그(`==> Parameters:`)로 잡는다

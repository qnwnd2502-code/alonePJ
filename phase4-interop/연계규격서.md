# OO기관 첨부파일 연계 규격서 (v1.3)

> 회사에서 연계를 맡으면 **이런 문서 한 장**을 받는다. 상대 서버 소스는 절대 못 본다.
> 이 문서만 보고 자바 코드를 짜야 한다. **규격서 읽기가 연계의 첫 번째 기술이다.**

## 1. 개요

| 항목 | 내용 |
|---|---|
| 연계 형태 | 실시간 API (HTTP) |
| 프로토콜 | HTTPS (운영) / HTTP (개발계) |
| 데이터 형식 | JSON |
| 문자셋 | UTF-8 |
| 인증 방식 | **API Key** |
| 운영 서버 | `https://openapi.기관.go.kr` |
| 개발계 서버 | `http://partner:8000`  (본 실습 환경) |

## 2. 인증

발급받은 `serviceKey` 를 아래 둘 중 한 방식으로 전달한다.

| 방식 | 위치 | 예시 |
|---|---|---|
| 방식 1 (구) | 쿼리스트링 | `?serviceKey=eGov-DEMO-KEY-2026-abcdef123456` |
| 방식 2 (권장) | HTTP 헤더 | `Authorization: Bearer eGov-DEMO-KEY-2026-abcdef123456` |

* 키 누락 또는 불일치 시 **HTTP 401** 과 함께 오류 메시지를 반환한다.
* **키는 소스에 하드코딩하지 말 것.** 환경변수 또는 별도 설정으로 주입한다.

## 3. 엔드포인트

### 3.1 파일 목록 조회

```
GET /openapi/file/list
```

응답 (200)

| 필드 | 타입 | 설명 |
|---|---|---|
| `resultCode` | String | `00` 이면 정상 |
| `resultMsg` | String | 결과 메시지 |
| `totalCount` | Number | 전체 건수 |
| `items[]` | Array | 파일 목록 |
| `items[].atchFileId` | String | 첨부파일 ID. **다운로드 시 이 값을 사용** |
| `items[].orignlFileNm` | String | 원래 파일명 (사용자가 올린 이름) |
| `items[].streFileNm` | String | 저장 파일명 (서버 내부용) |
| `items[].fileStreCours` | String | 저장 경로 |
| `items[].fileMg` | String | 파일 크기 (byte) |
| `items[].creatDt` | String | 등록일자 |

> ⚠ `fileStreCours` 는 **당 기관 서버 내부 경로**이며, 연계 기관에서 직접 접근할 수 없다.
> 파일 실물이 필요하면 3.2 다운로드 엔드포인트를 사용할 것.

### 3.2 파일 다운로드

```
GET /openapi/file/download?atchFileId={첨부파일ID}
```

* 응답: `application/octet-stream` (바이너리)
* 존재하지 않는 ID: **404**

### 3.3 헬스체크

```
GET /openapi/health
```
* 인증 불필요. 응답 `{"status":"UP"}`

## 4. 오류 코드

| HTTP | 의미 | 우리 쪽 조치 |
|---|---|---|
| 401 | 인증 실패 (키 없음/불일치) | 키 확인. **재시도해도 소용없다** |
| 404 | 대상 없음 | 요청한 ID 확인 |
| 500 | 상대 기관 서버 오류 | 재시도 대상 |
| 503 | 상대 기관 점검 중 | 재시도 대상. 점검시간 사전 공지됨 |
| (응답 없음) | 타임아웃 | 재시도 대상. **멱등성 주의** |

## 5. 유의사항

* 당 기관 정기점검: 매월 셋째 주 일요일 02:00 ~ 06:00
* 초당 호출 제한: 10 TPS
* 연계 기관 IP 는 사전 등록 필요 (화이트리스트)

## 6. 파일 연계 (야간 배치) — v1.3 추가

API 연계와 **별개의 연계**다. 대량 자료는 실시간 호출이 아니라 파일로 주고받는다.

### 6.1 전송 방식

| 항목 | 값 |
|---|---|
| 프로토콜 | SFTP (SSH File Transfer Protocol, 22/TCP) |
| 접속 정보 | `eaiuser@<당 기관 SFTP>` — 계정·비밀번호는 별도 공문 |
| 상대 폴더 | `/outbox` (chroot 안이라 사용자에게는 최상위로 보임) |
| 처리 완료분 | `/outbox/archive` 로 이동 |
| 방화벽 | 연계 기관 IP 사전 등록 필요 (API 화이트리스트와 **별건**) |

### 6.2 파일명 규칙

```
SUCH-YYYYMMDD-NNNN.dat
 │     │        └ 당일 순번 (0001 부터)
 │     └ 생성일자
 └ 업무구분 (SUCH = 수혜자)
```

### 6.3 완료 표시

당 기관은 파일을 다 쓴 뒤 **같은 이름 + `.done`** 빈 파일을 만든다.

```
SUCH-20260908-0001.dat        <- 자료
SUCH-20260908-0001.dat.done   <- "다 썼다" 는 신호
```

> **`.done` 이 없는 `.dat` 는 가져가지 말 것.** 당 기관 배치가 아직 쓰는 중일 수 있다.

### 6.4 전문 레이아웃 (고정길이)

* 문자셋: **EUC-KR**
* 개행: **CRLF**
* 레코드 길이: **47 바이트** (개행 제외)

| 위치 | 길이 | 항목 | 형식 | 비고 |
|---:|---:|---|---|---|
| 1 | 8 | 기관코드 | 영숫자 | 좌측정렬, 우측 공백 |
| 9 | 20 | 성명 | 한글 | 좌측정렬, 우측 공백 |
| 29 | 8 | 생년월일 | YYYYMMDD | |
| 37 | 10 | 금액 | 숫자 | **우측정렬, 좌측 0 채움** |
| 47 | 1 | 구분 | 1/2/3 | 1신규 2변경 3취소 |

> **길이는 글자 수가 아니라 바이트 수다.** EUC-KR 에서 한글 1글자 = 2바이트.
> `"김유신"` 은 6바이트를 차지하고 남은 14바이트는 공백이다.

### 6.5 재전송

* 자료 오류 시 당 기관이 **같은 파일명으로** 재전송할 수 있다.
* 연계 기관은 **동일 파일의 중복 적재를 방지**해야 한다. (처리이력 관리)

### 6.6 처리 주기

| 시각 | 주체 | 내용 |
|---|---|---|
| 23:00 | 당 기관 | 배치 생성 → `/outbox` 에 파일 + `.done` |
| 06:00 | 연계 기관 | SFTP 수신 → 검증 → 적재 → `archive` 이동 |

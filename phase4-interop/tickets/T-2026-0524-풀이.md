
## 결함 3 — 가리는 기계가 번호를 못 알아봤다 (MaskingUtil.maskText)

```
A   900101-1234567    하이픈
B   8505052345678     붙여씀
C   770707 1234567    띄어씀
```

```
고치기 전  \\d{6}-\\d{7}          숫자6 + 하이픈 + 숫자7         → A 만
고친 뒤    \\d{6}[-\\s]?\\d{7}    숫자6 + (하이픈|공백 있거나 없거나) + 숫자7   → A B C
```

주석에는 "하이픈 없는 것도 가린다" 고 적혀 있었다. **주석은 약속일 뿐, 실제로 하는 일은 코드가 정한다.**

참고 : C 는 `maskRrn` 에서 7번째 글자가 `-` 가 아니라서 fail-closed 로 전부 `*` 가 된다. 새는 것보다 낫다.

## 정규식 읽는 법 (오늘 처음)

```java
Pattern.compile("...")                    // ① 형광펜에 찾을 모양을 입력
RRN_IN_TEXT.matcher(text)                 // ② 문장에 댄다
    .replaceAll(m -> maskRrn(m.group()))  // ③ 칠해진 것마다 바꿔 끼운다 (m.group() = 찾은 글자)
```

부품을 **이어 붙이면 "그리고 이어서"** 다. "또는" 이 아니다.
`[-\\s]` = 이 중 하나, `?` = 앞 부품이 있어도 되고 없어도 됨.

## 회신에 들어가야 할 것 (코드로 못 고치는 부분)

1. **이미 남은 것** — 기관 서버 로그, 우리 aisvc 로그에 원본이 있다 → 해당 기간 로그 파기 (파기 기록 남김)
2. **이미 나간 것** — 외부 LLM 업체로 원본이 갔다. 우리가 못 지운다 → 업체에 삭제 요청 + 확인서.
   기관 개인정보 담당자가 유출 신고 대상인지 판단할 수 있게 **건수·기간·항목** 을 정리해 준다
3. 현실에서는 업체 로그(④)를 못 본다. **"안 나갔다" 는 ②③ 우리 쪽 로그로만 증명할 수 있다**

## 남은 숙제 (다음 사람 몫)

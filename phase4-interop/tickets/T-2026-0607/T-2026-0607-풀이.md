
## 판정

| # | 원인 | 근거 | 주체 | 요청 |
|---|---|---|---|---|
| 1 | 이력 없는 사람(lee)을 생각 안 한 코드 | `NullPointerException` + `at com.study...CounselController.history(:84)` `list.size()` | **B 우리 SI** | 우리가 고친다 |
| 2 | 외부 LLM 서버 접속 불가 | boot : `HttpServerErrorException 500` (상대가 답은 했다) → aisvc 로그 : `URLError ... Name or service not known` | **D 업체** (+C) | 업체에 장애 문의 / 우리 제품은 500 대신 "외부 AI 일시 장애" 안내 |
| 3 | 방화벽에서 막힘 | `Caused by: ConnectTimeoutException` + **aisvc 로그에 10:33 기록 없음** + 2번은 같은 주소로 연결 성공 | **A 인프라팀** | "신청서 정책(.15→.100:443)이 10:33부터 동작 안 함. 만료·변경 확인 요청" |

★ 2번과 3번은 화면 증상("잠시 후 다시 시도")이 똑같았다. 가른 것은 **상대가 답을 했나(500) / 안 했나(timeout)** 와 **상대 로그에 기록이 있나**.

## 누구를 부를지 가르는 순서

```
1. at com.study 가 처음 나오는 줄이 '넘어진 곳' 이다          → 우리 코드면 우리(B)
2. 상대가 상태코드(500 등)로 '답은 했다'                      → 상대 서버 안의 문제. 상대 로그를 본다
     우리 제품이면 우리가 꺼내 본다 → 거기서 또 바깥(업체)이 원인이면 업체(D)
3. 답이 아예 없다(timeout) + 상대 로그에 기록도 없다             → 가는 길(방화벽·네트워크) → 인프라팀(A)
```

★ 에러가 나면 데이터나 상대부터 의심하게 된다(1번을 "인프라팀 DB" 로 판정했다). **`at com.study` 가 위에 있으면 넘어진 건 우리다.**
